# Crypto Pattern Analyzer

Docker-сервис для почасового исследования рынка Binance. Он динамически выбирает ликвидные USDT-пары, анализирует только закрытые свечи на нескольких таймфреймах, сравнивает текущую ситуацию с историческими аналогами, сохраняет все данные в PostgreSQL и отправляет отчёт в Telegram.

> Сервис не подключается к торговому аккаунту, не хранит Binance API key и не открывает сделки. Метки `BUY` и `SELL` — исследовательская классификация, а не гарантия результата.

## Что реализовано

- автоматический выбор наиболее ликвидных Spot-пар Binance;
- исключение стейблкоинов и leveraged-токенов `UP`, `DOWN`, `BULL`, `BEAR`;
- таймфреймы `15m`, `1h`, `4h`, `1d`;
- анализ доходности, RSI, EMA20/EMA50, ATR, объёма, Bollinger Bands, тела/теней свечи и пробоя 20 свечей;
- поиск ближайших исторических аналогов с нормализацией признаков;
- отдельная историческая базовая вероятность для роста и падения;
- multi-timeframe aggregation;
- публичные futures-метрики: funding rate и open interest для сильнейших кандидатов;
- PostgreSQL: свечи, признаки, сигналы, история запусков и Telegram-доставок;
- почасовой встроенный scheduler;
- Telegram-отчёты и команды;
- HTTP API с необязательной защитой `API_KEY`;
- автоматическое применение SQL-схемы при запуске;
- Docker Compose с одним `.env`.

## Быстрый запуск

```bash
cd crypto-analyzer
cp .env.example .env
```

Заполните в `.env` минимум:

```dotenv
POSTGRES_PASSWORD=длинный_случайный_пароль
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=id_вашего_чата
API_KEY=длинный_случайный_api_key
```

Затем:

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f analyzer
```

Проверка:

```bash
curl http://localhost:8085/health
curl -H "X-API-Key: ВАШ_API_KEY" http://localhost:8085/api/v1/signals/latest
```

Остановка:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `crypto_postgres_data` и не удаляются обычной командой `docker compose down`.

## Один файл настроек

Все параметры находятся в `.env`. Других ручных настроек не требуется.

Основные параметры:

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `MAX_SYMBOLS` | `150` | Число самых ликвидных пар; `0` — все подходящие пары |
| `MIN_24H_QUOTE_VOLUME` | `1000000` | Минимальный 24h объём в котируемом активе |
| `ANALYSIS_INTERVALS` | `15m,1h,4h,1d` | Анализируемые интервалы |
| `KLINE_LIMIT` | `1000` | Исторические свечи на пару и таймфрейм |
| `SCAN_MINUTE` | `2` | Минута каждого часа для запуска скана |
| `NEAREST_NEIGHBORS` | `40` | Число ближайших исторических аналогов |
| `MINIMUM_SAMPLES` | `120` | Минимум исторических точек |
| `MINIMUM_PROBABILITY` | `0.58` | Минимальная доля целевого исхода среди аналогов |
| `MINIMUM_EDGE` | `0.06` | Минимальное преимущество над базовой частотой |
| `MULTITF_SIGNAL_THRESHOLD` | `0.12` | Минимальный итоговый multi-timeframe score |
| `REPORT_TOP_N` | `10` | Максимум BUY и SELL кандидатов в отчёте |

## Как рассчитывается сигнал

Для каждой закрытой свечи формируется вектор признаков:

1. доходность за 1, 3 и 6 свечей;
2. RSI(14);
3. расстояние EMA20 от EMA50;
4. расстояние цены от EMA20;
5. ATR(14) в процентах;
6. объём относительно предыдущих 20 свечей;
7. позиция и ширина Bollinger Bands;
8. тело, верхняя и нижняя тень свечи;
9. пробой максимума или минимума предыдущих 20 свечей.

Текущий вектор сравнивается со всеми допустимыми историческими точками того же символа и таймфрейма. Признаки стандартизируются, после чего выбираются ближайшие аналоги.

Для аналогов считаются:

- доля случаев, когда цена достигла заданного роста;
- доля случаев, когда цена достигла заданного падения;
- базовая частота этих событий на всей доступной истории;
- средний будущий результат;
- преимущество паттерна над базовой частотой.

Сигнал появляется только при достаточном числе наблюдений, вероятности, преимуществе над базой и совпадении нескольких таймфреймов.

`Confidence` — внутренний рейтинг качества сигнала от 0 до 100. Он не является гарантированной вероятностью сделки.

## Telegram

Бот автоматически отправляет отчёт после каждого завершённого скана.

Команды:

```text
/report            последний отчёт
/status            состояние последнего сканирования
/coin BTCUSDT      история сигналов одной пары
/scan              запустить сканирование вручную
/help              список команд
```

Команды принимаются только от `TELEGRAM_CHAT_ID`, указанного в `.env`.

## HTTP API

| Метод | Endpoint | Описание |
|---|---|---|
| `GET` | `/health` | Состояние сервиса и PostgreSQL |
| `GET` | `/api/v1/signals/latest?limit=20` | Сигналы последнего завершённого скана |
| `GET` | `/api/v1/scans/latest` | Последний запуск |
| `GET` | `/api/v1/coins/BTCUSDT?limit=30` | История сигналов пары |

Если `API_KEY` заполнен, передавайте его одним из способов:

```text
X-API-Key: value
Authorization: Bearer value
```

## PostgreSQL

Сервис автоматически создаёт таблицы:

- `crypto_scan_runs`;
- `crypto_symbols`;
- `crypto_candles`;
- `crypto_interval_analyses`;
- `crypto_signals`;
- `crypto_telegram_deliveries`;
- `crypto_schema_migrations`.

PostgreSQL наружу не публикуется. Доступ к нему есть только внутри Docker network.

## Источники данных

Используются официальные публичные endpoints Binance:

- Spot `exchangeInfo`;
- Spot `ticker/24hr`;
- Spot `klines`;
- USDⓈ-M Futures `openInterest`;
- USDⓈ-M Futures `fundingRate`;
- USDⓈ-M Futures `openInterestHist`.

Telegram работает через официальные методы Bot API `sendMessage` и `getUpdates`.
